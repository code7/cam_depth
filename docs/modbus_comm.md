# Modbus RTU 通讯说明

适用版本：`relative-delta-v1`  
设备角色：**PLC 为主站，本程序为从站**  
实现文件：`modbus_rtu.py`（协议）、`services/modbus_service.py`（业务状态机）、`cam_config.py`（默认配置）

---

## 1. 物理层与串口参数

| 项目 | 默认值 | 说明 |
|---|---|---|
| 接口 | RS-485 | 半双工，A/B 差分 |
| 波特率 | 9600 | 可在配置中修改 |
| 数据格式 | 8N1 | 8 数据位、无校验、1 停止位 |
| 从站地址 | 1 | 范围 1~247 |
| 地址基址 | 0 | 见第 3 节，可选 0 或 1 |
| 串口 | `/dev/ttySC0` | 树莓派现场常见设备名 |

建议在总线两端加 120Ω 终端电阻，并确保 PLC 与本设备共地。

---

## 2. 协议能力

- 协议：Modbus RTU
- CRC：CRC16，多项式 `0xA001`，初值 `0xFFFF`，**低字节在前**
- 寄存器数据：**大端**（高字节在前）
- 支持功能码：
  - `0x03` 读保持寄存器
  - `0x06` 写单个保持寄存器
  - `0x10` 写多个保持寄存器
- 不支持的功能码返回异常码 `01`
- 广播地址 `0`：执行写操作，但**不应答**
- 站号不是本机：不应答
- CRC 错误：丢弃，不应答
- `FC03`：读取数量 1~125；地址越界返回 `02`，数量非法返回 `03`
- `FC06`：地址越界返回 `02`；报文长度不对返回 `03`
- `FC16`：数量与字节数不一致返回 `03`；地址越界返回 `02`

异常响应格式：

```text
[从站地址][功能码 | 0x80][异常码][CRC低][CRC高]
```

| 异常码 | 含义 |
|---|---|
| `01` | 非法功能码 |
| `02` | 非法数据地址 |
| `03` | 非法数据值 |

## 3. 地址基址：必须现场确认

Modbus 有几种常见地址表示方式：

- 文档地址：`40001`、`40002`……
- 线上地址：实际报文中的 0 基地址或 1 基地址

本程序用 `addr_base` 适配两种情况：

| 文档地址 | 内部索引 | `addr_base=0` 线上地址 | `addr_base=1` 线上地址 |
|---|---:|---:|---:|
| 40001 | 0 | 0 | 1 |
| 40002 | 1 | 1 | 2 |
| 40003 | 2 | 2 | 3 |
| 40004 | 3 | 3 | 4 |
| 40005 | 4 | 4 | 5 |

注意：

- `addr_base` 只影响**线上地址**，寄存器含义不变。
- 日志里的 `40001/40002...` 已经换算成文档地址，不能仅凭日志判断基址。
- 需要看 Modbus 状态里的 `stats.req_addrs`（对方实际用过的线上地址），或直接抓串口报文。
- 典型现象：
  - PLC 用基址 0，配置成 1 → 读到全 0 或异常地址。
  - PLC 用基址 1，配置成 0 → 读到相邻寄存器，状态/距离错位。

## 4. 寄存器总表

| 文档地址 | 名称 | 访问 | 类型 | 说明 |
|---|---|---|---|---|
| 40001 | 设备状态 | R | `uint16` | 0=待机，1=测量中，2=完成，3=故障 |
| 40002 | 触发测量 | W | `uint16` | 写 1 启动测量，设备自动清零 |
| 40003 | A 面相对距离 | R | `int16` | 0.1mm/LSB，近负远正 |
| 40004 | B 面相对距离 | R | `int16` | 0.1mm/LSB，近负远正 |
| 40005 | 基准面校准 | W | `uint16` | 写 1 重新拟合基准面，设备自动清零 |

推荐一次读取 `40001~40005`，共 5 个寄存器，保证状态和距离来自同一时刻。

---

## 5. 寄存器逐项说明

### 5.1 40001 设备状态

| 值 | 名称 | 含义 |
|---:|---|---|
| 0 | 待机 | A/B 相机均已就绪，且当前没有任务 |
| 1 | 测量中 | 已受理测量/校准，正在取帧和计算 |
| 2 | 完成 | 本次测量/校准完成 |
| 3 | 故障 | 相机未就绪，或本次测量/校准失败 |

说明：

- **服务启动时 `40001=3`**：A/B 相机尚未打开或尚未完成初始化；两路相机都就绪后自动变为 `0`。
- 相机就绪条件：已打开、已出图、已标定基准面、已设置计算范围、没有正在执行的相机准备操作。
- 初始化期间写 `40002=1` 或 `40005=1` 不会开始任务，设备保持故障；等 `40001=0` 后再触发。
- 状态 `2/3` 会保持，直到下一次测量或校准；测量/校准失败产生的 `3` 不会因相机状态心跳自动清除。
- 没有单独的“清除故障”寄存器；再次写 `40002=1` 或 `40005=1` 即开始新任务。
- 故障原因**不占用寄存器**，需要看设备端日志或界面里的 `last_error`。

### 5.2 40002 触发测量

- PLC 写 `1`：启动一次测量。
- 设备受理后会把 `40002` 自动清 `0`。
- 只有值 `1` 会触发；写 `0` 或其他值不启动测量。
- `40001=3`（含相机未就绪）时触发会被拒绝，`40002` 仍会清零；等 `40001=0` 后再触发。
- 建议 PLC 写 `1` 后不要依赖回读保持 `1`，看到清零即表示已受理。
- **测量进行中不要重复写 `1`**：忙时写入会保留，当前任务结束后会再触发一次测量。
- 写请求的正常响应是原请求回显（功能码 `06`）。

### 5.3 40003 / 40004 A/B 面相对距离

- 物理含义：当前切面相对**最近一次校准基准面**的距离，不是相机到木块的绝对距离。
- 符号约定：
  - 靠近相机：负值
  - 远离相机：正值
- 单位：`0.1 mm/LSB`
- 数据类型：**有符号 16 位整数 `int16`**
- 寄存器可表示范围：`-3276.8 ~ +3276.7 mm`
- 业务无效阈值：`|距离| > 6000 mm` 直接判故障
- 由于编码量程更小，实际有效输出范围是 `-3276.8 ~ +3276.7 mm`；超过即故障，**不会截断**
- 只有在 `40001=2` 时数据才有效：
  - `40001=1`：仍是上一次结果
  - `40001=3`：本次失败，仍保留上一次结果，不能使用
- 测量完成时，设备先更新 `40003/40004`，再置 `40001=2`；读到 `2` 后距离已刷新。
- 校准（`40005=1`）**不会更新** `40003/40004`；校准后需要再触发一次测量才能刷新距离。

### 5.4 40005 基准面校准

- PLC 写 `1`：重新采集当前画面并拟合基准面。
- 设备受理后会把 `40005` 自动清 `0`。
- 状态流程与测量相同：`40001=1 → 2/3`。
- 校准会保存新的基准面系数和面心距离。
- 校准**不修改** `40003/40004`，也不做“清零”。
- 校准时应保证基准面/切刀参考状态稳定，否则会拟合到错误平面。

## 6. 状态机与触发流程

```text
上电/服务启动
    │
    ▼
40001 = 3 故障（A/B 相机未就绪）
    │
    │  A/B 相机均就绪
    ▼
40001 = 0 待机
    │
    ├── 写 40002=1 ──► 40002 清 0，40001=1 测量中
    │                       │
    │                       ├── 成功 ──► 更新 40003/40004，40001=2 完成
    │                       └── 失败 ──► 40001=3 故障（距离保持旧值）
    │
    └── 写 40005=1 ──► 40005 清 0，40001=1 测量中
                            │
                            ├── 成功 ──► 更新基准面，40001=2（距离不更新）
                            └── 失败 ──► 40001=3 故障
```

时序说明：

- `40002/40005` 的清零轮询周期约 20ms，通常写后很快能看到 `0`。
- 触发后约 2s 才取新帧（`measure_delay_s` 默认 2.0s）。
- 相机约 1 FPS，实际测量周期通常约 2.5~3.0s。
- `timeout_s` 默认 3.0s，是**延迟之后等待新帧的预算**，不是 PLC 的串口响应超时。
- 相机请求的内部超时：
  - 测量：`timeout_s + measure_delay_s + 5s`
  - 校准：`timeout_s + measure_delay_s + 10s`
- PLC 侧建议为一次测量/校准预留至少 15~20s，期间轮询 `40001`，不要重复触发。

## 7. 距离编码

### 7.1 编码公式

```text
raw = round(mm × 10)
```

有符号 16 位：

```text
raw >= 32768 时，signed = raw - 65536
mm = signed / 10
```

### 7.2 示例

| 物理距离 | 寄存器原始值（十六进制） | PLC 按 `int16` 显示 |
|---:|---:|---:|
| `0.0 mm` | `0x0000` | 0 |
| `+0.2 mm` | `0x0002` | +0.2 |
| `+12.3 mm` | `0x007B` | +12.3 |
| `-0.2 mm` | `0xFFFE` | -0.2 |
| `-1.0 mm` | `0xFFF6` | -1.0 |
| `-12.3 mm` | `0xFF85` | -12.3 |

如果 PLC 显示 `65534` 而不是 `-0.2`，说明寄存器被配置成了无符号 `uint16`，应改为 `int16`。

## 8. 报文示例

以下示例默认：

- 从站地址：`1`
- 波特率：9600，8N1
- CRC 低字节在前

### 8.1 `addr_base=0`

读取 `40001~40005`：

```text
请求：01 03 00 00 00 05 85 C9
响应：01 03 0A 00 02 00 00 00 02 00 03 00 00 B4 16
```

响应含义：

```text
40001 = 2      完成
40002 = 0      触发位已清
40003 = 2      A 面 +0.2 mm
40004 = 3      B 面 +0.3 mm
40005 = 0      校准位已清
```

触发测量（写 `40002=1`）：

```text
01 06 00 01 00 01 19 CA
```

触发校准（写 `40005=1`）：

```text
01 06 00 04 00 01 09 CB
```

### 8.2 `addr_base=1`

读取 `40001~40005`：

```text
请求：01 03 00 01 00 05 D4 09
响应：01 03 0A 00 02 00 00 00 02 00 03 00 00 B4 16
```

触发测量：

```text
01 06 00 02 00 01 E9 CA
```

触发校准：

```text
01 06 00 05 00 01 58 0B
```

### 8.3 负数距离响应

A 面 `-0.2 mm`，B 面 `+0.3 mm`：

```text
01 03 0A 00 02 00 00 FF FE 00 03 00 00 F0 0D
```

其中 `40003 = FF FE`，按 `int16` 解释为 `-2`，即 `-0.2 mm`。

### 8.4 异常响应

例如非法数据地址：

```text
01 83 02 C0 F1
```

含义：功能码 `03 | 0x80 = 0x83`，异常码 `02`（非法数据地址）。

## 9. PLC 侧推荐流程

### 9.1 启动

1. 读取 `40001`，确认通讯正常。
2. 服务刚启动时读到 `40001=3` 属于正常：A/B 相机还未打开或未完成初始化。
3. 等待 `40001` 变为 `0` 再触发测量；若长时间为 `3`，查看设备日志中的相机状态。
4. 测量/校准失败也会置 `3`，这时可查看 `last_error` 后重新触发。

### 9.2 测量

1. 写 `40002=1`（FC06）。
2. 收到 FC06 回显后，轮询 `40001`。
3. `40001=1`：测量中，继续等待。
4. `40001=2`：读取 `40001~40005`，取 `40003/40004`，按 `int16 × 0.1mm` 解释。
5. `40001=3`：本次失败，`40003/40004` 是旧值，不可使用。

### 9.3 写响应丢失时

如果写 `40002=1` 后没有收到响应：

1. 先读 `40001`。
2. 如果 `40001=1` 或 `2`，说明请求已受理，**不要重复写触发**，否则会多测一次。
3. 如果 `40001=3`，当前没有任务在执行；可能是相机未就绪导致拒绝，也可能是任务已失败。看设备日志后，等相机就绪再重试一次。
4. 如果 `40001=0` 且 `40002=0`，说明请求可能没送到，可以重发一次。

### 9.4 校准

1. 写 `40005=1`。
2. 轮询 `40001`，等待 `2/3`。
3. 校准成功后，`40003/40004` 仍是上一次测量值。
4. 需要新距离时，再触发一次 `40002=1`。

## 10. 配置参数

配置位置：`config/cam_config.enc`，由配置服务读取。

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `auto_start_modbus` | `true` | 是否自动启动 Modbus 服务 |
| `modbus.port` | `/dev/ttySC0` | RS-485 串口 |
| `modbus.baudrate` | `9600` | 波特率 |
| `modbus.slave_addr` | `1` | 从站地址 |
| `modbus.addr_base` | `0` | 0 或 1，见第 3 节 |
| `modbus.timeout_s` | `3.0` | 延迟之后等待相机新帧的预算 |
| `modbus.measure_delay_s` | `2.0` | 触发后等待多久再取新帧 |

| `dist_signed` | `true` | 有符号距离 |
| `dist_abs_max` | `6000.0` | 业务无效阈值，单位 mm |

注意：`timeout_s` 不是 PLC 串口响应超时，也不是整个测量周期上限。

## 11. 已知行为与注意事项

1. **40002 / 40005 会自动清零**，这不是故障，是受理标志。
2. **测量中重复写 40002=1 会排队**，当前任务结束后会再测一次；PLC 应避免。
3. **不要同时写 40002 和 40005**：设备会先执行测量，校准位保留，测量结束后再执行校准。
4. **校准不清零距离寄存器**；校准后要再测量一次。
5. **40001=3 时 40003/40004 仍是旧值**，必须丢弃。
6. **只读寄存器被写不会报异常**：设备只记录告警，但仍会覆盖值；PLC 不应写 `40001/40003/40004`。
7. **距离寄存器是有符号 `int16`**，不是 `uint16`，也不是 32 位浮点。
8. **超过 ±3276.7mm 会报故障**；业务阈值 6000mm 更大，但寄存器编码量程更小，以编码量程为准。
9. **故障原因不在寄存器里**，只能看设备日志/界面。
10. **服务启动时 `40001=3` 是正常的初始化状态**：A/B 相机都就绪后自动变 `0`。
11. **广播写不会应答**，不建议用于触发测量。
12. **CRC 错误/站号不符不会应答**，PLC 需要自行重试。

## 12. 快速排查

| 现象 | 优先检查 |
|---|---|
| 完全无响应 | 站号、波特率、8N1、A/B 接线、终端电阻、串口设备名 |
| 能读但全是 0 | `addr_base` 是否反了；是否从未触发测量 |
| 读到的状态/距离错位 | `addr_base` 错一位 |
| 负数显示成 65534 | PLC 寄存器类型改成 `int16` |
| 40002 写 1 后马上变 0 | 正常，表示已受理 |
| 40001 一直为 1 | 相机服务离线、相机 Device busy、等待新帧超时；看日志 |
| 启动后 40001=3 | 正常，等待 A/B 相机初始化；若长时间不变，看相机日志 |
| 测量后 40001=3 | 看设备日志中的故障原因；旧距离不可用 |
| 校准成功但距离没变 | 正常，校准不更新距离；再触发测量 |
| 距离突然超量程 | 检查基准面、ROI、相机安装、标定是否有效 |
